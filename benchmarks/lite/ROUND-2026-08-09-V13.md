## 4. A correction this round makes to the previous one

§5.4 of the 2026-08-08 round says the `intent_role_mismatch` check "has been firing
intermittently all along (the gateway round, v9, v10 failed it; v7, v8, v11 passed)". That round
list belongs to the *`team`-has-one-chassis* defect, which fails as `intent_variant_mismatch`.
The ledger carries `intent_role_mismatch` as a FINAL reason on exactly two generations — **v10
and v12**. v3, v7, v8, v9 and v11 lost their one fixture to `intent_variant_mismatch` or
`malformed_response`.

The ledger stores only the final reason, so an attempt refused this way and recovered on the
retry leaves no row: intermittent firing stays consistent with the data without being shown by
it. What is measured is that it cost a whole generation twice.

## 7. Three setup facts worth keeping

- **`.env.bench` IS COMMITTED, and it is named exactly like a local secrets file.** It exists to
  BLANK the backend vars for the video bench, and its own header says "NO SECRETS BELONG HERE".
  This round wrote the gateway key, anon key and service-role key into it before `git status`
  showed it as ` M` rather than untracked — caught in the working tree, never staged, never
  committed, and `git log -- .env.bench` on this branch is empty. The eval config now lives in
  **`.env.bench.local`**: Vite loads `.env.[mode].local` after `.env.[mode]`, so it wins without
  touching the tracked file, and `.gitignore`'s `.env*` covers it. `git check-ignore -v` on a new
  env file is the two-second check that would have caught this before the write, not after.

- **`IP_HASH_SALT` is a Lite prerequisite, not a render-only one.** `liteLedgerConfigured()`
  requires at least 16 characters of it, so without one `/api/ai/lite/status` answers
  `not-configured` with the gateway key, the provider allowlist, ZDR and the enable flag all
  correct. It salts the ANONYMOUS per-IP quota hash, which an identity-bound eval never uses —
  so the failure has no relationship to the thing it blocks.
- **`npm run bench:preflight` reads the ENV FILE, not the process environment.** A token exported
  only in the shell leaves the free preflight failing `missing-credentials` for a reason that is
  not true, which is exactly the kind of false signal it exists to remove. `stamp-token.mjs`
  writes it into `.env.bench` instead. Preflight then passed with two expected warnings:
  one arm (no baseline), and a hand-supplied token that cannot refresh.
