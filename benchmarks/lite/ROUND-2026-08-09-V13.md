## 4. A correction this round makes to the previous one

§5.4 of the 2026-08-08 round says the `intent_role_mismatch` check "has been firing
intermittently all along (the gateway round, v9, v10 failed it; v7, v8, v11 passed)". That round
list belongs to the *`team`-has-one-chassis* defect, which fails as `intent_variant_mismatch`.
The ledger carries `intent_role_mismatch` as a FINAL reason on exactly two generations — **v10
and v12**. v3, v7, v8, v9 and v11 lost their one fixture to `intent_variant_mismatch` or
`malformed_response`.

The ledger stores only the final reason, so an attempt refused this way and recovered on the
retry leaves no row: intermittent firing stays consistent with the data without being shown by
it. What is measured is that it cost a whole generation twice.

### 5.1 `one-line` holds an empty reserved band — the defect no gate saw

The brief is *"a cinematic one-line lower third identifying Aisha Rahman. No invented role or
organization."* The model resolved `lt32` Scrim and emitted **two** lines, leaving the second
sample empty. The hold frame paints the name into the top of the scrim and leaves roughly a third
of the panel below it blank. The update frame confirms it is structural rather than a data
artifact: driven with new copy, the name re-wraps to two lines and the lower band is still empty.

`documentary-subject` is the control — same `lt32`, both lines filled, and it renders a short rule
above the name that `one-line` does not have. So the chassis has a tighter arrangement available
and this generation did not get it.

**No machine signal fired.** `fieldCount: 2`, no rule codes, no warnings, `motionSettled` true —
and `bench-field-unpainted` is silent because the field CAN paint; it simply had nothing in it.
This is the exact shape `src/ai/AGENTS.md` records from the previous round ("painted its name,
reserved a band under it, drew nothing there") reappearing through a different door.

**Owner: model decision, so the fix is free and permanent** (plan §4). A brief that names one line
should produce `lines` of length one; the schema already allows it.

### 5.2 Every strap in the bank is bottom-left, and most are the same density

`alignment: left` on **30 of 30**; `density: standard` on 27 of 30 (three `airy`, zero `tight`).
`lt25` answered three unrelated briefs — `event-identity`, `story-headline`, `skin-luxury-runway` —
with the same rule-above-name-above-caps arrangement, differing mainly in hue.

Placement is a platform decision now (`keepChassisZone`; every audited chassis declares bottom-left),
so this is not a model failure. But it means **the sameness tripwire in doctrine principle 3 cannot
be read off this bank at all** — the variety has to come from the chassis mix, and with six lower
thirds there is not much of it. This is an argument for the widening in plan §5, not against it.

### 5.3 A style brief is answered with colour, not with design

All three style-stress fixtures resolved to a house chassis recoloured:

| brief | resolved | what actually changed |
|---|---|---|
| brutalist poster | `lt05` | red accent instead of amber |
| neon synthwave | `lt15` | purple panel, magenta accent, rounded corners |
| luxury runway | `lt25` | gold rule and gold caps instead of amber |

None changed weight, shape language, or layout. This is the honest current ceiling of a

Worth stating plainly so a future round does not read it as a regression.

### 5.4 `long-name` drops the brand accent and is the heaviest frame in the bank

`lt11` House Strap, whose catalog entry reads *"amber accent, dark broadcast-width panel"*, came
back with a **white** accent bar on a pure black panel. Both lines wrap, so the strap carries four

not clipped, but it is the frame least like the design it claims to be. A bespoke palette is legal;
worth watching whether the model reaches for one when the copy gets long.

## 8. Three setup facts worth keeping

- **`.env.bench` IS COMMITTED, and it is named exactly like a local secrets file.** It exists to
  BLANK the backend vars for the video bench, and its own header says "NO SECRETS BELONG HERE".
  This round wrote the gateway key, anon key and service-role key into it before `git status`
  showed it as ` M` rather than untracked — caught in the working tree, never staged, never
  committed, and `git log -- .env.bench` on this branch is empty. The eval config now lives in
  **`.env.bench.local`**: Vite loads `.env.[mode].local` after `.env.[mode]`, so it wins without
  touching the tracked file, and `.gitignore`'s `.env*` covers it. `git check-ignore -v` on a new
  env file is the two-second check that would have caught this before the write, not after.

- **`IP_HASH_SALT` is a Lite prerequisite, not a render-only one.** `liteLedgerConfigured()`
  requires at least 16 characters of it, so without one `/api/ai/lite/status` answers
  `not-configured` with the gateway key, the provider allowlist, ZDR and the enable flag all
  correct. It salts the ANONYMOUS per-IP quota hash, which an identity-bound eval never uses —
  so the failure has no relationship to the thing it blocks.
- **`npm run bench:preflight` reads the ENV FILE, not the process environment.** A token exported
  only in the shell leaves the free preflight failing `missing-credentials` for a reason that is
  not true, which is exactly the kind of false signal it exists to remove. `stamp-token.mjs`
  writes it into `.env.bench` instead. Preflight then passed with two expected warnings:
  one arm (no baseline), and a hand-supplied token that cannot refresh.
