## What batch 1 found, and what it cost to fix

The first 25 cells came back 20/25 with **all five failures on one job** - `lecture-speaker`, on
five different mark/palette pairings, while the other four jobs were 20/20. Mark shape and palette
family predicted nothing; the brief did. That separation is what crossing the ingredients bought,
and one pinned pair per brief could not have produced it.

Attributed from the ledger: `line_count_invalid` at attempt 2 with one repair. Retrieval offers
`ls17` Lectern first for an academic brief - the best semantic match - and `ls17` declares a
minimum of three lines against a two-line brief. Checked free with `retrieveLiteReferenceSet`:
the same brief retrieves `ls17` first with NO mark at all, so this was never a regression from
§3.6.2; drawing the seven wells is what made it reachable for marked requests and therefore
measurable.

**Fixed by re-picking rather than refusing** (`line_count_chassis_reselected`), the same ladder
the mark and palette repairs already follow. The five failing cells re-fired **0/5 -> 5/5**, every
one landing on `lt11` - which is exactly the chassis the deterministic search selects (first entry
holding two lines, accepting `person`, with 39 characters of supporting capacity against a
38-character role), where the model's own taste had chosen `ls17`.

Two details the implementation had to get right, both measured rather than assumed:

- **Room for the copy is judged against the lines in hand**, not by comparing the two chassis's
  declared capacities. `ls17` declares the largest capacity in the bank (134), so the
  chassis-to-chassis test would have made this repair impossible exactly where it is needed.
- **The mark repair's own swap now checks line capacity too.** It compared characters and not
  lines, so it could fix a mark by moving onto a design that cannot hold the graphic.

## The four survivors are TRANSIENT, and that is as far as this round can attribute them

`badge-square` x2, `banner-wide` x1, `shield-tall` x1, four different jobs, four different
palettes. All four re-fired **machine-usable on a re-roll**, so they are sampling variance rather
than a structural pairing failure - no cell of the grid is reproducibly broken.

**Their rule codes are unavailable, and that is a real gap rather than an omission.** A refusal
records its codes in the ledger; bench rows now go to the memory ledger (because the prod ledger
rejects the `adjustments` write until migration 0043 is applied), and nothing exposes a memory
row. Flipping the bench back to the prod ledger for one attribution run did not work either -
Vite did not restart on that env change, so the round quietly used the memory ledger again, which
is only visible by checking that the prod table gained no rows.

## Three harness faults this round exposed

1. **The §3.2 deploy-order hazard, for real.** The first attempt failed 8/8 with
   `rejection_reason = ledger_update`: the bench server writes to the production ledger and
   `ai_generations.adjustments` does not exist there yet. Every generation 500'd on the outcome
   write AFTER its model call was billed. Stopped at 8 of 25 rather than run to completion.
2. **A wholesale failure reads as free.** The eval's cost line reported **$0.0000** for that run
   while the ledger had booked ~$0.011, because `scripts/ai-lite-eval.mjs` sums successful rows
   only. The known gap, arriving at the worst possible moment.
3. **The round ceiling counts ATTEMPTS, not cells**, so batches sized as 40 cells delivered 31 and
   left 18 holes in the grid at exactly the offsets the next batch skipped past. Filled by naming
   the missing ids. A matrix runner that walks the grid should compute its next offset from what
   the previous batch actually covered.

And one that cost nothing but time: stamping a fresh bearer token rewrites `.env.bench.local`,
which makes Vite restart the bench server - firing a round into that window dies `ECONNREFUSED`.
Poll the server before starting a paid round.

## What is still open

- **No human frame review.** 96.8% machine-usable is not 96.8% airable, and the §2 value gate is
  a blind human read. Frames and clips are in `lite-eval-out/` (gitignored - archive with
  `npm run eval:archive`).
- **Repair rates are invisible to the bench.** The endpoint returns no `adjustments` to the
  caller, so the matrix can say a result was usable but not how often the platform had to repair
  it to get there. §3.2 made that visible in production; the bench still cannot see it.
- **The brand audit's rules do not run over generated frames** - only over catalog chassis with a
  fixture mark. The funnel §4.4 describes ends at the runtime bench and field paint.
